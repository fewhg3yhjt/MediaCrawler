# 微博爬取与归档使用指南（tombkeeper 全量微博存档）

本文档记录本项目针对 **微博（weibo）** 平台爬取与可视化的完整使用方式，以 **tombkeeper（UID 1401527553，25087 条微博）** 为默认目标。

## 1. 整体流程

```
微博 API (m.weibo.cn)
   │  .venv 里跑爬虫（增量/全量）
   ▼
data/weibo/jsonl/creator_contents_*.jsonl   ← 原始数据（JSONL，按天分文件）
   │  tools/weibo_jsonl_to_html.py（可下载图片）
   ▼
data/weibo/tombkeeper_weibo.html            ← 单文件 HTML 时间线（双击即看、离线可用、可搜索）

定时任务（每周日 03:00）→ scripts/update_archive.ps1 → 自动完成上面两步
```

## 2. 环境要求

- Windows（本指南基于 Windows / PowerShell）
- 虚拟环境：项目自带 `.venv`（Python 3.11），以下用 `.venv\Scripts\python.exe`（简称 `py`）
- 浏览器：CDP 模式（`config/base_config.py` 中 `ENABLE_CDP_MODE = True`）会自动拉起本机 Chrome/Edge，**需要桌面会话**
- 登录态：缓存于 `browser_data/cdp_wb_user_data_dir`，有效期内**无需扫码**；失效后需手动扫码一次

## 3. 常用命令

### 3.1 全量抓取（首次，约 5~9 小时）

```powershell
.venv\Scripts\python main.py --platform wb --lt qrcode --type creator
```

- 从第一页翻到底，抓取全部微博（含全文）。
- 首次运行（无任何 jsonl 存档）自动走全量。
- 中途 Ctrl+C 中断安全：JSONL 逐行追加落盘，已有数据不丢；下次重跑会自动去重（见 §5.2）。
- 全量模式翻页自带随机 1~2s 限速，单线程请求（见 §5.5），5~9 小时为正常耗时。

### 3.2 全量/断点续跑（一次性把全部历史抓完）

```powershell
# 方式一：环境变量（临时）
$env:WEIBO_FULL_CRAWL=1
.venv\Scripts\python main.py --platform wb --lt qrcode --type creator

# 方式二：一键脚本 -Full
powershell -ExecutionPolicy Bypass -File scripts\update_archive.ps1 -Full
```

- 无存档 → 从第 1 页全量抓；有存档 → 从"最旧已存位置"**继续**抓（中断后重跑会续跑而不是从头再来）。
- 日常增量更新**不要**用该模式（会从头扫一遍）。

### 3.3 增量抓取（日常更新，分钟级）

```powershell
.venv\Scripts\python main.py --platform wb --lt qrcode --type creator
```

- 与全量**同一命令**：爬虫启动时读取现有 `creator_contents_*.jsonl` 里最新一条 `note_id`，翻页到该边界即停。
- 首次无存档 = 全量，有存档 = 增量，无需手动区分。

### 3.4 生成 HTML 时间线（含本地图片下载）

```powershell
.venv\Scripts\python tools/weibo_jsonl_to_html.py `
  --input data/weibo/jsonl/creator_contents_*.jsonl `
  --output data/weibo/tombkeeper_weibo.html `
  --download-images --workers 6
```

- 输出：`data/weibo/tombkeeper_weibo.html`（自包含单文件，双击打开即用）。
- `--download-images`：把微博图片下载到 `data/weibo/images/`（已存在自动跳过，支持续传）。
- 不带该参数则不下载图片，HTML 引用线上 sinaimg 直链。
- 脚本参数详见 `tools/weibo_jsonl_to_html.py` 顶部 docstring。

### 3.5 一键更新（抓取 + 生成）

```powershell
# 增量（默认，日常/定时任务用）
powershell -ExecutionPolicy Bypass -File scripts\update_archive.ps1

# 全量/断点续跑
powershell -ExecutionPolicy Bypass -File scripts\update_archive.ps1 -Full
```

幂等可重复执行，输出日志到 `logs\`。

### 3.6 定时任务（已注册）

任务名 `tombkeeper_weibo_archive`，每周日 03:00 自动执行 §3.5（增量模式）。

```powershell
# 查看任务
schtasks /query /tn tombkeeper_weibo_archive /fo LIST

# 手动立即运行一次
schtasks /run /tn tombkeeper_weibo_archive

# 删除任务
schtasks /delete /tn tombkeeper_weibo_archive /f
```

> 注意：任务为**"仅用户登录时运行"**，电脑关机/未登录时不会执行（错过可手动 `/run`）。

## 5. 关键实现说明

### 5.1 分页修复
微博 m.weibo.cn API 已把创作者主页分页从 `since_id` 改为 **`page` 参数**。原代码用 `since_id` 会永远返回第一页导致死循环。修复位置：`media_platform/weibo/client.py` 的 `get_notes_by_creator` / `get_all_notes_by_creator_id`。

### 5.2 增量与去重
- `store/weibo/__init__.py` 新增 `get_archive_stats()` / `get_latest_note_id()`：读存档条数、最旧/最新 note_id。
- `get_all_notes_by_creator_id(..., stop_note_id=..., start_page=...)`：翻到边界即停（增量）；支持起始页码（断点续跑）。
- `store/weibo/_store_impl.py` 的 JSONL 实现：启动时加载已有 note_id 集合，重复条目不重复写盘（边界/续跑重叠安全）。

### 5.3 登录优化
- `pong()`：`/api/config` 的 `login` 字段对有效会话经常误报 false。改为检测 **`SUB` cookie** 存在即视为已登录，有效会话不再触发扫码。
- 扫码（`media_platform/weibo/login.py` + `tools/crawler_util.py`）：二维码不再全屏弹窗，改为保存到 `data/login_qrcode.png` 并提示；等待超时由 600s 降到 **120s**，带进度日志。

### 5.4 配置项
`config/base_config.py` / `config/weibo_config.py` 中与本次相关的：
- `WEIBO_CREATOR_ID_LIST = ["1401527553"]` —— 爬取对象（可改成其他博主 UID）
- `ENABLE_GET_COMMENTS = False` —— 关闭评论抓取（提速、降风险）
- `ENABLE_WEIBO_FULL_TEXT = True` —— 拉取长文全文（逐条多发一个请求，是耗时主要来源）
- `ENABLE_GET_MEIDAS = False` —— 不下载媒体原图/视频
- `SAVE_DATA_OPTION = "jsonl"` —— 数据格式
- `WEIBO_CREATOR_PAGE_SLEEP_SEC = (1.0, 2.0)` —— 创作者翻页随机间隔（秒）
- `WEIBO_FULL_CRAWL = False` —— 全量/断点续跑开关（也可用环境变量 `WEIBO_FULL_CRAWL=1`）

### 5.5 流控（防风控）
全量爬取时对微博的请求频率控制：
- **翻页限速**：每页之间随机 `1~2s`（`WEIBO_CREATOR_PAGE_SLEEP_SEC`），列表请求 ≤ ~0.5 次/秒。
- **全文限速**：每条长文全文请求后 sleep `2s`（`CRAWLER_MAX_SLEEP_SEC`）。
- **单线程**：`MAX_CONCURRENCY_NUM = 1`，无突发并发。
- **失败重试**：请求失败自动重试 5 次（间隔 3s）；遇 432/解析错误会 sleep 2s 并刷新 cookie。
- **IP 代理**：默认关闭（`ENABLE_IP_PROXY=False`）。若频繁被风控，可配置快代理/豌豆HTTP 账号后开启（需自行准备代理账号）。
- 全量约 2500 页、5~9 小时，为上述限速下的正常耗时。

### 5.6 全量断点续跑
- 全量模式（`WEIBO_FULL_CRAWL=True`）下，中断后重跑会从"最旧已存位置"（按已存唯一条数估算页码，前留 5 页缓冲）继续，重叠部分由去重兜底。
- 日常增量更新无需关心，仅首次全量/续跑时使用该模式。

## 6. 编码约定

- 本项目所有生成文件（jsonl、HTML、日志、.ps1）**均为 UTF-8**；`.ps1` 带 BOM 以便 PowerShell 正确解析。
- Windows 系统命令（如 `schtasks`）按 GBK 输出时，展示前会转码为 UTF-8。

## 7. 常见问题

**Q1: 抓取时报"扫码登录超时 / 进入扫码流程"？**
登录态过期。手动跑一次 `scripts\update_archive.ps1`，出现二维码后用微博 App 扫码，之后恢复自动运行。

**Q2: 定时任务没跑？**
该任务仅在用户登录时运行；确认电脑开机且未锁屏，或用 `schtasks /run` 手动触发。

**Q3: 想重新全量抓一遍？**
删除/移走 `data/weibo/jsonl/creator_contents_*.jsonl` 后重跑 §3.1 即为全新全量；若只想续跑中断的全量，用 `WEIBO_FULL_CRAWL=1` 或 `-Full`（§3.2）即可接着抓。

**Q4: 全量抓取会不会被封？**
已内置流控：翻页随机 1~2s、全文 2s、单线程、失败自动重试。若仍频繁被风控（403/432/验证码），可开启 IP 代理（§5.5）。

**Q5: HTML 里图片加载失败？**
线上直链可能被微博防盗链；用 `--download-images` 生成离线版（推荐）。

**Q6: 视频能看吗？**
当前不下载视频。微博视频为带过期签名的 mp4 直链，本地可能失效；可点卡片"原文 ↗"跳微博观看。
