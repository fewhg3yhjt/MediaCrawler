## 已知缺口

- **2024-03 ~ 2025-02 约一年无数据**。已实测确认：weibo.com/ajax/statuses/mymblog 接口在该时间段直接跳过（page 175=2025-03-06 → page 177=2024-02-28），**是微博接口侧的数据缺失**，非爬虫漏抓。
- 若需补这段，需另寻通道（第三方存档等），本方案无解。

## 过程中的关键修复

1. **分页机制**：m.weibo.cn API 由 `since_id` 改为 `page` 分页，原代码死循环 → 已改。
2. **深度历史**：m.weibo.cn 只提供最近 ~1970 条 → 接入 **weibo.com/ajax/statuses/mymblog**（需桌面登录态），可翻到 2011 年，全量回填 2.9 万条。
3. **登录优化**：pong() 误判导致每次扫码 → 改检测 SUB cookie；二维码不再全屏弹窗（存文件）；等待超时 600s→120s。
4. **会话恢复**：weibo.com 桌面会话缺 ALF cookie 会被判未登录 → SSO 重认证自动补全，中途风控失效自动恢复。
5. **防卡死**：详情全文请求曾挂起数小时（60s 超时失效）→ 全部网络请求加 `asyncio.wait_for` 硬超时 40s。
6. **防误判**：风控临时返回空列表被当"到底"提前结束 → 空列表重试+探更深页确认。
7. **增量更新**：读存档最新 note_id 翻到边界即停；jsonl 写入去重；全量支持断点续跑。

## 自动化（已配置）

- `scripts/update_archive.ps1`：一键增量抓取+生成 HTML（日志落盘 `logs/`）
- `scripts/check_archive.ps1`：进度快照（条数/速率/ETA），30 分钟一次自动记录
- `scripts/gen_html.ps1`：仅重新生成 HTML（含增量图片下载）
- **定时任务**：
  - `tombkeeper_weibo_archive`：每周日 03:00 增量更新（仅登录时运行）
  - `tombkeeper_weibo_checkpoint`：每 30 分钟进度快照（跑完后可删）
- 注意：定时任务须"仅在用户登录时运行"（CDP 要桌面会话）；登录态过期时需手动跑一次扫码

## 日常使用

```powershell
# 增量更新（抓取 + 生成 HTML）
powershell -ExecutionPolicy Bypass -File scripts\update_archive.ps1

# 只重新生成 HTML（图片增量下载）
powershell -ExecutionPolicy Bypass -File scripts\gen_html.ps1

# 看当前进度
powershell -ExecutionPolicy Bypass -File scripts\check_archive.ps1
```
