# 微博图片采集使用说明

> 更新于 2026-10-29 · 对应新架构阶段性实现；旧微博爬虫继续独立运行。

## 1. 当前可用能力

任务框架现在注册了 `text`、`images`、`video`、`audio`、`comments` 与 `metrics` 六项能力，可分别选择；来源支持指定微博、用户主页、当前账号收藏/赞过和本地 JSONL。正文保存清洁文本、原始文本和完整性标记。旧存档正文完整性未知；长微博会按需请求移动详情页，无法确认完整时返回 `partial`，不把截断片段标成全文。视频和音频只接受详情响应中的直链，不把播放页地址当作媒体文件；下载时流式写盘并校验容器签名。评论使用微博 `hotflow` 分页，只采集一级评论并受单独数量上限约束，不将接口附带回复宣称为完整楼中楼。互动计数独立保存点赞、评论和转发数量，并带观测时间；它不代表点赞用户名单。未注册的能力和未知选项会在执行前拒绝。

除命令行外，现在提供独立的本地任务页面。网页和 CLI 共用 `CollectionApplication`，按同一请求契约执行；未选择图片下载时不会写图片文件。打开页面不会读取浏览器登录目录，默认先公开访问；只有提交任务时明确勾选“允许本次任务使用项目中已登录的微博账号”，本次任务才可能使用该会话。登录受限后，页面需要用户再点击扫码授权按钮才会打开微博官方登录页。会话留在本机浏览器上下文中，不导出 Cookie。每个服务进程同一时间只执行一个采集任务，登录目录也有跨进程占用锁。

账号范围是调用方提供的本地数据隔离键，不证明微博登录身份；更换账号应使用不同范围标识。网页数据、任务历史、图片和 ZIP 均保存在指定工作目录。

### 1.1 本地任务页面（推荐用于链接抓图）

启动服务：

```powershell
.venv\Scripts\python.exe scripts\serve_weibo_images.py
```

打开 <http://127.0.0.1:8767/>，可选“单条微博”“用户主页”“我的收藏”或“我赞过”。用户主页可填数字 UID 或 `/u/数字UID` 链接；账号来源不需要 URL，但必须勾选“允许本次任务使用项目中已登录的微博账号”。用户主页和账号来源均可设置最多发现多少条微博（默认 1000，最高 10000）。选择的正文、图片、视频、音频、评论和互动计数能力会逐条应用。评论可单独设置一级评论数量上限（默认 100，最高 500）。达到数量上限会标记为部分完成，并显示本次发现条数；接口结束只表示本次扫描结束，不保证覆盖全部历史。页面还可分别选择是否下载图片、是否包含转发原文媒体，以及本次任务是否允许使用项目登录态；可观察进度、取消任务、重试未完成部分、查看正文、图片、评论及互动计数、播放已下载的音视频、下载单个文件或打包下载成功媒体。只选某项能力时不会调用其他采集器。刷新页面不会停止运行中的任务；服务重启后，历史和未完成任务会保留，未完成项标记为中断并可恢复。

命令行支持 `--port`、`--workspace`、`--browser-profile`、`--account-scope`、`--interval` 和 `--login-timeout`。服务只绑定 `127.0.0.1`，默认端口为 8767。不要对外暴露此本地服务。

### 1.1 直接给微博链接，下载并返回图片

```powershell
.venv\Scripts\python.exe scripts\collect_weibo.py `
  --url '<微博链接>' `
  --browser-profile browser_data\cdp_wb_user_data_dir `
  --account-scope my-account
```

链接模式支持桌面微博链接（含短码）、移动端 `detail/status` 链接和数字微博 ID；会忽略定位参数和评论锚点，统一得到微博 ID。CLI 的 `--url` 仍用于单条微博；用户主页来源通过请求文件或本地页面选择。

链接模式默认下载图片。`--metadata-only` 只保存地址，`--include-retweeted` 包含转发原文图片；使用请求文件时应在 `collect.images` 中设置这些选项。

`--browser-profile` 仅在用户明确授权后使用指定目录，登录会话留在浏览器内，不导出 Cookie。它不会自动扫码；会话失效时结果明确标记 `restricted`，原因为 `login_required` 或 `access_restricted`。Cookie 文件与浏览器目录不能同时指定。

命令输出逐张图片的状态、原地址、本地路径，以及 `outputs.manifest` 和 `outputs.gallery`，分别为本次结果清单及本地图片预览页。预览页仅展示已下载的本地图片，不在只解析地址时偷偷加载远程图片。

## 2. 指定微博，下载图片

请求样例：[weibo_images_detail.json](./examples/weibo_images_detail.json)。其中微博 ID 是示例，执行前替换为需要处理的目标。

```powershell
.venv\Scripts\python.exe scripts\collect_weibo.py `
  --request-file docs\examples\weibo_images_detail.json `
  --account-scope my-account
```

需要登录态时添加 `--cookie-file <本地文件路径>`。文件仅放单行 Cookie 请求头值，不包含 `Cookie:` 前缀，不应纳入版本控制。此脚本不创建或验证账号会话。

## 3. 从本地存档提取图片地址

请求样例：[weibo_images_archive.json](./examples/weibo_images_archive.json)，从收藏集合选择最多 20 条微博，只保存已有图片地址；没有可用图片信息的记录可能追加详情请求。

```powershell
.venv\Scripts\python.exe scripts\collect_weibo.py `
  --request-file docs\examples\weibo_images_archive.json `
  --account-scope my-account
```

`--archive-dir` 可指定 JSONL 所在目录。可在来源中加入 `note_ids` 选择特定记录，集合与 ID 取交集；指定 ID 不在该集合时返回错误。

`download=false` 只保存元数据，不下载文件。改成 `true` 可补下载；已经成功保存且校验和匹配的资源会复用。

旧 JSONL 的图片字段不能证明完整性，因此直接复用时可能返回 `partial`。若需要重新请求详情核对，设置图片选项 `verify_manifest=true`。本地地址过期或访问受限会记录失败，不自动宣称没有图片。

## 4. 采集正文

请求样例：[weibo_text_detail.json](./examples/weibo_text_detail.json)。正文也是 `collect` 中的独立能力：

```json
{
  "source": {"type": "detail", "note_ids": ["<微博链接或ID>"]},
  "collect": {"text": {"require_full_text": true}}
}
```

使用 `--request-file` 执行。只选择正文时不会调用图片采集器；正文与图片同时选择时会共享该任务内的详情响应。`require_full_text` 默认为 `true`。长微博若详情响应未带完整内容，系统会再读取微博移动详情页；若该请求受限或未能确认完整，返回 `partial` 和 `full_text_unavailable`。设为 `false` 可以接受存档片段，但结果仍会标明 `complete=false`。不带完整性证明的旧 JSONL 正文不会自动标为全文成功。

## 5. 视频和音频

请求样例：[weibo_media_detail.json](./examples/weibo_media_detail.json)。`video`、`audio` 与图片、正文一样是独立能力，可分别加入或省略：

```json
{
  "source": {"type": "detail", "note_ids": ["<微博链接或ID>"]},
  "collect": {
    "video": {"download": true, "include_retweeted": false},
    "audio": {"download": true, "include_retweeted": false}
  }
}
```

只下载详情响应提供的 MP4 直链和 `audio_url`。仅有 `page_url` 播放页时不会伪装成文件，结果标记为部分完成。大文件以流的方式写入临时文件，再检查 MP4/WebM/FLV、MP3/AAC/Ogg/MP4 容器签名，校验后才原子归档；视频上限 1 GiB，音频上限 100 MiB。校验是容器签名检查，不等同于完整解码。请求 `download:false` 可只保存直链元数据。直链下载只允许微博/CDN 域名，跨域重定向会在请求前拒绝。

## 6. 状态与产物

默认新增产物在 `data/weibo/collection/`，可用 `--workspace` 更改：

| 位置 | 内容 |
| --- | --- |
| `tasks.sqlite3` | 请求快照、已发现工作项、集合归属、各次能力结果 |
| `images/assets.sqlite3` | 按账号范围、所属微博、资源标识和类型建立的文件索引 |
| `images/<内容哈希>.<真实格式>` | 校验后原子保存的图片，同一内容可共享文件 |
| `video/`、`audio/` | 校验后的内容寻址媒体文件及独立索引 |
| `reports/<任务ID>/report.json` | 各能力结果、正文、媒体路径、错误及任务状态 |
| `reports/<任务ID>/index.html` | 本地正文、图片预览和音视频文件入口 |
| `web_jobs.sqlite3` | 本地网页的 URL、选项、进度、错误码及任务历史；不保存 Cookie、二维码或登录凭据 |
| `exports/<任务ID>-media.zip` | 网页生成的媒体包及清单，只包含已成功下载的文件 |

业务结果在 `capability_runs.result`，包含每张图的原始地址、所属微博、本地路径、状态和安全错误码。命令输出任务 ID、发现数量、各能力状态数量及终止原因。旧 JSONL、旧图片目录与旧网页均不改写。

各能力结果区分 `succeeded/no_content/partial/failed/restricted`。图片列表未确认完整、图片部分失败、或所需全文未取得时标记部分完成；登录限制或非有效详情不能记为无内容。

## 7. 重试和中断恢复

使用原请求文件和原账号范围：

```powershell
.venv\Scripts\python.exe scripts\collect_weibo.py `
  --request-file docs\examples\weibo_images_detail.json `
  --account-scope my-account `
  --resume-task <上次输出的任务ID>
```

恢复时先处理已持久化工作项，再重放来源；跳过同任务已成功或已确认无内容的能力。部分失败的微博会再次解析，已下载文件通过校验和复用，只重下失败或损坏资源。

更改任何请求内容后应提交新任务，不使用原任务 ID 恢复。新任务 `update.default=missing` 检查已有资源；`refresh` 重新下载所选资源。已成功能力在恢复中会跳过，需复查时提交新任务。

任务级异常会输出任务 ID，取消记录保留在状态库中；强制退出可能保留 `running`，可用原任务 ID 恢复。第一版仅支持单进程运行，不要并发恢复同一任务。

退出码：`0` 为所选范围成功，`2` 为存在部分完成/能力失败，`1` 为请求或任务级失败，`130` 为键盘中断。`source_exhausted` 只表示本次有限来源结束，不代表平台全部历史内容已齐全。

## 8. 当前能力边界

当前已落地的是正文、图片、视频、音频、一级评论和互动计数能力，指定微博、用户主页、当前账号收藏/赞过与本地 JSONL 来源，以及 CLI 和独立本地任务页面。账号来源只使用本次任务明确选择的当前登录会话；不能指定或读取其他人的收藏/赞过列表。收藏接口有总数，赞过接口没有可靠总数，分页结束只代表本次接口扫描结束。2026-10-28 经用户授权使用本地登录态验证了收藏和赞过第一页：各返回 20 条，首条均可解析为统一微博对象；只检查这一页，未调用正文采集器或媒体下载器，未展示或持久化响应内容，也未验证全量分页。评论仅使用 `hotflow` 一级评论分页；未实现回复分页或点赞用户清单。互动计数是单次观测快照；来源响应有完整计数时复用，缺失时按需请求详情。用户主页和账号来源分页当前无持久化远端页码检查点；中断恢复会重放并去重已发现微博。不包含通用依赖图和跨任务能力结果缓存。新页面仍独立于旧 `weibo_web` 管理台。后续扩展通过注册来源、采集器和适配器完成，不在每个来源内重复加入采集逻辑。

### 8.1 抓取用户主页

请求样例：[weibo_creator_text_images.json](./examples/weibo_creator_text_images.json)。将 `creator_id` 改为数字 UID，并按需编辑 `collect` 中的能力；省略的能力不会运行。

```powershell
.venv\Scripts\python.exe scripts\collect_weibo.py `
  --request-file docs\examples\weibo_creator_text_images.json `
  --account-scope my-account
```

网页可在“采集范围”中切换到“用户主页”，填写 UID 或 `https://weibo.com/u/<UID>`，并设置 `max_posts`，默认 1000、上限 10000。达到上限会返回 `partial` 和 `limit_reached`；未达到上限时，连续两个有效空页表示本次分页接口已结束，不能据此证明账号全部历史都可见。分页检查点尚未实现，中断后恢复会重放前面页面并按微博 ID 去重。需要登录时，只有本次任务明确允许并在受限后点击扫码，才使用项目登录态。

### 8.3 当前账号收藏与赞过

网页来源“我的收藏”和“我赞过”针对当前已登录账号。提交前必须显式勾选允许本次任务使用项目微博登录态；受限时仍需再点击扫码授权。页面先从登录会话确认当前账号 UID，再请求所选列表，不会接收目标 UID，也不读取其他账号的收藏/赞过数据。CLI 请求文件使用 `source.type=self_feed`，并通过显式 `--browser-profile` 或 `--cookie-file` 提供当前账号会话；CLI 不自动扫码。

两种来源都可设置 `limits.max_posts`（1–10000，默认 1000），达到上限会报告 `partial/limit_reached`。收藏接口包含 `total_number`，可用来校验发现数；赞过接口没有可靠总数，连续空页只作为本次分页结束的启发式信号，不能宣称完整覆盖全部历史。分页检查点尚未实现，恢复任务会重放并去重已发现微博。2026-10-28 经用户授权各请求过收藏和赞过第一页，返回结构与当前 `all_fav` / `likelist` 解析器匹配；这不代表全量分页或所有账号都已验证。接口变化或权限限制应显示为失败/受限，不能当作空列表。

CLI 请求样例：[weibo_self_favorites_text.json](./examples/weibo_self_favorites_text.json)。示例只选正文能力；本地执行时需显式提供当前登录态，例如已授权的 `--browser-profile <目录>` 或 `--cookie-file <文件>`。不要把 Cookie 文件提交到仓库。也可将来源的 `feed_type` 改成 `liked`，并独立选择其他已注册能力。

### 8.4 互动计数

请求样例：[weibo_metrics_detail.json](./examples/weibo_metrics_detail.json)。`collect.metrics` 独立采集点赞数、评论数和转发数，不采集点赞用户名单。用户主页与账号列表的来源响应已有完整计数时直接复用并记录本地观测时间；指定微博或来源计数缺失时，只有选中 `metrics` 才请求微博详情。`update.default=refresh` 会刷新计数快照。接口缺少部分字段时结果为 `partial/metrics_incomplete`，不会把缺失值填成 0。该能力不会触发媒体下载或评论列表请求。

### 8.2 采集热评流

请求样例：[weibo_hot_comments_detail.json](./examples/weibo_hot_comments_detail.json)。`comments.max_count` 限制一级评论数量，范围 1–500，默认 100；同一请求可和正文或媒体能力一起选择。评论不会触发媒体下载；接口未选中的评论能力不会请求。

网页勾选“采集热评流一级评论”后可设置数量上限。评论数据保留评论 ID、作者、正文、时间、赞数和本次返回顺序。达到上限但游标仍有后续数据时标记 `partial/comments_limit_reached`；游标重复或分页空档会显式失败。当前不抓回复分页，不将一级评论响应里偶尔附带的回复当作完整楼中楼；`hotflow` 返回范围也不代表微博全部评论。

设计与对象关系见 [微博按需采集架构设计](./微博按需采集架构设计.md)。
