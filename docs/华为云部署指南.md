# 华为云部署指南（MediaCrawler-微博定制版）

> 目标：代码托管 GitHub（私有仓）+ 华为云 ECS 运行，先全量爬取，再每日增量自动化。

## 一、总体架构

```
[GitHub 私有仓库] --clone--> [华为云 ECS Ubuntu]
                                  │
                     uv + Python 3.x + Playwright Chromium
                                  │
                 ┌────────────────┴───────────────┐
                 │  weibo_web (8095 归档前台)       │  <- 公网 IP 直接访问（先不加认证）
                 │  api (8080 WebUI 可选)           │
                 │  cron 每日 03:00 run_daily.py    │
                 │  数据: data/ (JSONL+图片+HTML)   │
                 │  SQLite: weibo_web/weibo_relations.db
                 └────────────────────────────────┘
```

## 二、云服务器选型建议（华为云）

| 项 | 建议 |
|---|---|
| 规格 | 2C4G 起步（全量爬取耗时，4C8G 更稳） |
| 磁盘 | 100G 系统盘 + 100G 数据盘（挂 `/data` 或直接大系统盘） |
| 系统 | Ubuntu 22.04/24.04 LTS |
| 带宽 | 5M 以上（图片/HTML 归档 + 前台浏览） |
| 安全组 | 放行 22(SSH)、8095、8080、5432（如用 postgres） |
| 地域 | 华东/华南（离微博机房近，延迟低） |

> 注意：数据会重新跑，3.4G 本地数据**不需要**迁移。

## 三、环境初始化（云服务器上次执行）

```bash
# 1) clone 代码（私有仓需要先在服务器配好 Git 凭据，或用 HTTPS + PAT）
git clone <your_repo_url> ~/mediacrawler
cd ~/mediacrawler

# 2) 一键初始化（装系统依赖 + uv + .venv + playwright + cron）
bash deploy/setup_cloud.sh
```

脚本会自动：
- apt 安装 Python/字体/浏览器系统库
- 安装 `uv`
- 创建 `.venv` 并按 `requirements.txt` 装依赖
- `playwright install chromium` + 系统依赖
- 建 `data/ logs/` 目录
- 写 cron（每日 03:00 跑 `scripts/run_daily.py`）

`setup_cloud.sh` 运行后需**手动**完成下面两步。

## 四、首次扫码登录（云上重新扫码）

1. 启动归档前台（这样能在浏览器里看二维码）：
   ```bash
   nohup .venv/bin/python -m weibo_web.main > logs/web.log 2>&1 &
   ```
2. 开一个 SSH 终端，跑一次爬虫触发登录扫码：
   ```bash
   .venv/bin/python main.py --platform wb --lt qrcode --type creator --save_data_option jsonl
   ```
3. 浏览器访问 `http://<公网IP>:8095/api/login/qrcode`，能看到二维码 → 手机微博扫码 → 登录成功。

> 登录态保存在 `wb_user_data_dir/`，之后自动复用，无需再扫码（除非过期）。

## 五、全量爬取 → 增量自动化

### 1) 全量阶段（首日/首周）

```bash
cd ~/mediacrawler
# 同步关注/粉丝到关系库
.venv/bin/python scripts/sync_follows_fans.py

# 把要跟踪的用户设为"全量"模式（在 8095 前台"人脉"页把每个用户改为 full）
# 或 SQL: update users set crawl_mode='full' where tracked=1;

# 跑全天全量链（收藏/赞过/creator/跟踪用户，带看门狗，中途断了自动续）
.venv/bin/python scripts/run_daily.py --full
```

建议用 `tmux` 或 `nohup` 放后台：
```bash
nohup .venv/bin/python scripts/run_daily.py --full > logs/run_full.log 2>&1 &
tail -f logs/run_full.log
```

### 2) 增量阶段（全量完成后）

确认全量结束后，用 cron 每日定时跑增量：
```bash
crontab -e
# 加入（setup_cloud.sh 已自动加）：
# 0 3 * * * cd ~/mediacrawler && .venv/bin/python scripts/run_daily.py >> ~/mediacrawler/logs/cron_daily.log 2>&1
```

增量链：`sync_follows_fans → batch_crawl_tracked → creator 增量`，每步都有单实例锁、超时保护，失败只记录不中断整链。

> **调用注意**：`run_daily.py` 内部有文件锁（`logs/run_daily.lock`），cron 与手动重复触发时第二个会直接退出，不会双开。

## 六、启动 Web 服务（公网访问）

```bash
# 微博归档前台 (8095) —— 任务管理/人脉/数据迁移/图片代理
nohup .venv/bin/python -m weibo_web.main > logs/web.log 2>&1 &

# （可选）MediaCrawler WebUI (8080)
nohup .venv/bin/uvicorn api.main:app --host 0.0.0.0 --port 8080 > logs/api.log 2>&1 &
```

浏览器访问：`http://<公网IP>:8095`

### 简单加个反向代理（推荐，可后续再做认证）
```bash
apt-get install -y caddy
cat > /etc/caddy/Caddyfile <<EOF
:8095 {
    reverse_proxy 127.0.0.1:8095
}
EOF
systemctl restart caddy
```

## 七、安全提醒（重要）

当前方案是"先用公网 IP 访问、暂不加认证"。**8095 前台没有登录鉴权**，任何人知道 IP 就能启动/停止你的爬虫任务、看数据。上线后建议尽快：

1. Caddy/nignx 加 `basic_auth`。
2. 或华为云安全组只放行你的出口 IP。
3. 8080/8095 端口不要 0.0.0.0 长期裸奔。

## 八、备份策略（必须）

数据不会自动备份，建议每日：
```bash
# 每日 tar 备份到本地目录（再加 rsync/对象存储传到另一台）
0 4 * * * cd ~/mediacrawler && tar czf /backup/weibo_$(date +\%F).tar.gz data weibo_web/*.db && find /backup -type f -mtime +7 -delete
```
关键数据：`data/weibo/jsonl/`（微博正文）、`data/weibo/images/`（图片）、`weibo_web/weibo_relations.db`（关系库）。

## 九、风控与限速

- 云服务器 IP 是数据中心 IP，微博风控力度比家宽大。
- 项目已内置限速（`WEIBO_PC_PAGE_SLEEP_SEC`、`WEIBO_CREATOR_PAGE_SLEEP_SEC`），**不要调太激进**。
- 若被风控（报错/限流），拉长间隔；必要时上代理（`ENABLE_IP_PROXY`）。
- 全量爬完进增量后，每天只有少量新增请求，风控风险大幅下降。

## 十、常见问题

- **登录态失效** → 删除 `wb_user_data_dir/` 后重跑一次爬虫触发扫码。
- **chromium 起不来** → `.venv/bin/playwright install-deps chromium` 补装系统库。
- **端口被占** → `lsof -i:8095` 找到旧进程 kill 掉。
- **日志在哪** → `logs/`（web.log / run_full.log / daily_*.log / cron_daily.log）
